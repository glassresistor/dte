--- DTE (oracle-guided mask, 1 iteration) ---
Output: 'The team will receive the report quickly and will definitely review it before the meeting.'

ED:     3
Iterations: 1

Key findings:
1. On simple grammar, both perform equally — the errors are obvious enough
   that even a raw prompt handles them. DTE's advantage is the GUARANTEE,
   not the outcome on easy inputs.

2. On code repair, DTE produces exactly minimal diffs while the raw LLM
   over-edits (removes docstrings, changes whitespace). This is the core
   DTE value proposition: structural locality as a hard constraint, not a
   prompt-level hope.

3. DTE is faster on code because the focused prompt (showing only suspect
   lines + test output) requires less generation than "rewrite this code."

4. The raw LLM's over-editing is consistent with §2.1 of REPORT_DTE.txt:
   "LLMs systematically over-edit: they rephrase stylistic choices, alter
   tone, refactor unrelated code." The DTE mask prevents this by
   construction.

5. Speed difference is small (~1-2s) because both use the same underlying
   model. DTE's verification loop adds one oracle call but the LLM call
   itself is shorter (more focused prompt → fewer tokens generated).
